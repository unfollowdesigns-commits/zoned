# Setup

You do not need hardware, a Supabase account, or a phone to see this working.
Start at step 1 and stop wherever you like.

## 1. Run the tests (2 minutes, no hardware)

```bash
npm install
npm test
```

64 tests covering the physiology maths. This is the fastest way to confirm the
project works on your machine.

## 2. Run the dashboard on demo data (2 minutes, no hardware)

```bash
npm run dev
```

Open http://localhost:3000. You are looking at six weeks of *simulated* nights
and workouts, scored by the same code that will score your real ones. The demo
data is generated by `packages/core/src/synthetic.ts` and is seeded, so it looks
the same every time.

This is genuinely useful while you wait for a strap to arrive: you can judge the
layout and the scoring before you own a sensor.

## 3. Run the phone app (30–60 minutes, needs a strap)

The mobile app talks to Bluetooth hardware, which **Expo Go cannot do**. You need
a development build — a real app installed on a real phone. There is no way
around this and it is the step most likely to take an afternoon the first time.

```bash
cd apps/mobile
npm install          # installs separately from the root, see note below
npx expo prebuild    # generates the native ios/ and android/ projects
npx expo run:android # or: npx expo run:ios
```

Requirements:
- **Android**: Android Studio, and a phone in developer mode with USB debugging.
- **iOS**: a Mac with Xcode. A free Apple ID works; the build expires after 7
  days and needs reinstalling.

Then: open the **Sensor** tab, wet the strap electrodes, put it on, tap **Scan**,
tap your strap. The **Live** tab should show your heart rate within a few
seconds.

> **Why does the mobile app install separately?**
> React Native pins React 18; Next.js 15 needs React 19. One hoisted copy of
> React cannot satisfy both, and the resulting error (`Cannot read properties of
> null (reading 'useContext')`) is baffling if you have not seen it before. So
> `apps/mobile` sits outside the npm workspace and keeps its own
> `node_modules`. `apps/mobile/metro.config.js` tells Metro where to find
> `@zoned/core`.

## 4. Record your first data

1. **Live** tab → choose **Rest reading** → **Start recording**.
2. Sit still and breathe normally for three minutes.
3. **Stop and save**.
4. **Today** tab → pull down to refresh.

You will see HRV. You will *not* see a recovery score yet: recovery compares
today against your own baseline, and one reading is not a baseline. Record
sleep for about a week and it becomes meaningful — the app tells you so rather
than showing you a confident number built on nothing.

For sleep: start a **Sleep** recording before bed and stop it in the morning.

## 5. Cloud sync (optional)

Everything above works fully offline. Sync is only needed if you want the web
dashboard to show your real data, or want a backup.

1. Create a project at [supabase.com](https://supabase.com) (the free tier is
   plenty).
2. Run `supabase/migrations/0001_init.sql` in the SQL editor.
3. Copy `.env.example` to `.env` in `apps/mobile`, and to `.env.local` in
   `apps/web`, filling in your project URL and publishable (anon) key.
4. Restart both apps. The **Sensor** tab grows a **Sync now** button.

The publishable key is safe to ship in a client — row level security in the
migration is what actually protects your data, and every table is restricted to
rows owned by the signed-in user.

## Troubleshooting

**Scan finds nothing.** Almost always one of: the strap is dry (wet the
electrodes), the strap is already connected to another app or watch (close it),
or Android permissions were declined (uninstall and reinstall to be asked
again).

**Heart rate shows but HRV stays blank.** HRV needs at least 30 clean beats.
If it stays blank for minutes, the sensor is probably not reporting RR intervals
— check the model against `docs/HARDWARE.md`.

**Artifact rate above 5%.** A fit problem. Tighten the strap and re-wet it.

**`npx expo run:android` fails on the first run.** Usually a missing Android SDK
component. The error names it; install it in Android Studio's SDK Manager and
run again.
